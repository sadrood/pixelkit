# 人生之书 · 玩法加厚版 v2 —— 机制说明书

> 这一版解决的不是"文笔"，是**可玩性**。
> 原稿 13 个抉择 × 3 选项，理论路径 3¹³ 条，但每条路径读到的文本 95% 相同——因为**抉择之间没有状态门槛、没有代价、没有不可逆**。v2 把这三层补齐。

---

## 0. 原稿 vs v2 对照

| 维度 | 原稿 | v2 加厚版 |
|---|---|---|
| 状态反馈 | 只有灯 +1 | 五维属性即时增减 + 灯谱等级 |
| 抉择门槛 | 无（3 个选项永远可选） | 9 处条件锁，锁死会显示原因 |
| 因果链 | 无 | 4 条不可逆标记，改写后续章节正文 |
| 随机性 | 只有出生性别 | 出生 4 项随机 + 每章之间抽 1 张人生事件卡（一生不重复） |
| 代价 | 无 | 部分抉择消耗年岁（复读 +1 年） |
| 结局 | 6 + 1 隐藏 | 每条世界线 12 种（7 主桶 + 2 隐藏 + 3 特殊），五条线合计 15 种不同结局文本 |
| 重玩驱动 | 无 | 成就 12 项 + 三类图鉴 + 二周目回响 |
| 周目 | 无 | 回响系统：预知（1）/ 改命（3） |
| 世界线 | 1 条 | 5 条（小城浮世 / 赛博·霓虹井 / 仙侠·照心灯 / 民国·雪与刀 / 校园·十七岁的灯） |
| AI 增强 | 无 | 可选接入任意 OpenAI 兼容接口，用于开局批注、结算散文、墓志铭；不配置亦完整可玩 |

## 0.1 已实现的世界线

| # | 世界线 | "灯"是什么 | 一句话 |
|---|---|---|---|
| A | 小城浮世 | 巷口的路灯 | 现实主义，一代人的迁徙 |
| B | 赛博 · 霓虹井 | 个人节点指示灯 | 被系统登记的一生 |
| C | 仙侠 · 照心灯 | 本命心灯（灯芯是执念） | 无灵根者的一生 |
| D | 民国 · 雪与刀 | 保甲的门灯 | 灯灭则屋易主 |
| E | 校园 · 十七岁的灯 | 学生 / 讲台上的台灯 | 四十年的讲台 |

五条线共用同一套引擎、同一套灯谱序号、同一套桶计分规则，**换的只是名字、场景与声口**。新增第六条的格式见第 10 节。

## 1. 开局随机化——"天注定，玩家不挑"

进入世界线后立即掷 4 次骰，玩家全程不能改：

| 项 | 取值 | 作用 |
|---|---|---|
| 性别 | 男 / 女 | 只影响代词与个别称谓（`{ta}` 爱人 / 异性同学，`{子}` 儿子/闺女），**不影响数值**，避免性别平衡问题 |
| 姓名 | 名单 10 选 1 | 纯文本 |
| 家境 | 家徒四壁 / 寻常人家 / 略有薄产 | 体魄 −1、心力 +1 ／ 无修正 ／ 积蓄 +2、人情 +1、心力 −1 |
| 天赋 | 好身板 / 钝感的心 / 小聪明 / 讨喜的脸 / 手气不错 | 对应属性 +2 |

五维基础值均为 **3**，叠满后范围 **0–10**。

> 设计意图：让"你无法选择出生"这件事本身成为第一记重锤，和序章"你出生了，你没办法不活"呼应。

## 2. 五维属性

| 属性 | 含义 | 典型用途 |
|---|---|---|
| 体魄 vit | 身体、精力 | 扛病、扛夜班、扛事故 |
| 心力 men | 抗压、意志 | 失业、丧亲、坦白委屈时的门槛 |
| 才学 arc | 技能、学历 | 转型、写书、升学线的硬门槛 |
| 人情 soc | 人脉、关系网 | 聚会、借钱、临终打电话的门槛 |
| 积蓄 coin | 钱 | 辞职陪护、接母亲同住、回老家的硬门槛 |

**属性是"能不能选"的钥匙，也是随机事件的判定依据。** 灯决定你是什么样的人，属性决定你此刻够不够格。

## 3. 灯谱 v2

18 盏不变，但每盏从"亮/不亮"改成 **−1 ~ 3 的等级**：

- **亮（1–3）**：可累加。等级 ≥2 在结算时额外加 1.5 分权重。
- **暗（−1）**：被掐灭过。侧栏显示为划掉的暗灯。
- **转化**：第十章 B 把【欠】−1、【孝】+1，是全书唯一的"赎罪"路径。

派生三个结算指标：

| 指标 | 算法 | 用途 |
|---|---|---|
| 灯芯值 | 所有正等级之和 | 人生浓度 |
| 韧度 | 灯被掐灭过的累计次数 | 隐藏结局《九死未悔》门槛（≥3） |
| 主灯 | 获胜桶内等级最高的那盏 | 生成墓志铭 |

## 4. 随机人生事件

- 每两章之间抽 1 张，**同一事件一生只遇一次**（防重复、防刷）。
- 每个事件有 `when`（年龄段/属性门槛）与 2–3 个 `outcome`，**按属性判定走第一条满足的分支，否则兜底最后一条**。
- **每条世界线 20 张卡，五条共 100 张**。同一条线跑两遍，撞到的卡完全可能不同。

各条线的事件主题（部分）：

|---|---|
| 小城浮世 | 车间事故 / 老屋漏雨 / 旧友借钱 / 房东涨租 / 母亲的电话 / 体检报告 / 老同事走了 / 老巷拆迁 / 厂房失火 |

| 仙侠 · 照心灯 | 矿脉塌方 / 药庐漏雨 / 验脉 / 照心井封了 / 替人守夜 / 灯冢失火 / 山门裁员 / 一株野药 |

## 8. 二周目：回响

每通关一次 **+1 回响**，跨周目累计。在抉择界面可以花：

| 能力 | 花费 | 效果 |
|---|---|---|
| 预知 | 1 | 显示该选项的后果摘要（灯/属性变化），不剧透正文 |
| 改命 | 3 | 回退到上一次抉择之前，重选一次（含已应用的属性与灯） |

这是把"重开一局"从惩罚变成资源的做法——玩家刷周目不再是为了重来，是为了攒回响去撬开某一条特定路线。

## 9. 结局判定：分桶计分

### 9.1 为什么不用"主灯映射"

原稿按"累计最亮的一盏"映射结局，实测问题很大：1600 局随机压测下 **48% 都落在《灯与雪》**，而《执灯人》只出现 2 次。原因是【念】【归】的来源太多（3 个抉择 + 2 个事件），天然膨胀。

### 9.2 现在：18 盏灯分成 7 个互斥桶

| 桶（结局） | 灯 | 权重 |
|---|---|---|
| 传灯者 | 传、融 | 等级和 ×1，等级 ≥2 额外 +1.5 |
| 执灯人 | 守、孝、担 | 同上 |
| 点灯的远行者 | 路、踮、远 | 同上 |
| 滚烫的人 | 滚、追 | 同上 |
| 守灯的人 | 暖、诚、桥 | 同上 |
| 缺一角的灯 | 欠、藏 | 同上 |
| 灯与雪 | 念、痴、归 | 同上 |

取总分最高的桶。**每个桶的灯完全不重叠**，所以不会再出现某组灯天然通胀的问题。

### 9.3 覆盖层（优先于桶）

| 结局 | 条件 |
|---|---|
| 点亮万盏灯（隐藏） | 念·担·路·孝·传·归·暖 七盏全部 ≥1 |
| 九死未悔（隐藏） | 韧度 ≥ 3 |
| 金灯无芯 | 积蓄 ≥ 8 且灯芯值 ≤ 14 |
| 独照 | 人情 ≤ 1 且灯芯值 ≥ 12 |
| 雪落无声 / 灰雪无声 / 玄霜无声 | 【归】类灯 ≥3 且【欠】类灯为 0 |

> 阈值不是拍脑袋定的：压测里"贪财策略"（每章优先选加钱最多、加灯最少的选项）能达到的最高积蓄是 9–10，而灯芯值的**理论下限是 13**（13 个抉择每个至少点亮一盏）。所以《金灯无芯》原来的 `≤11` 是**永远打不出来的死结局**，现已改为 `≥8 且 ≤14`，实测在混合策略下约 1/2000 命中，属于"刻意为之才拿得到"的稀有结局。

### 9.4 实测分布

**全随机乱点**（2500 局，五条线混合）：

```
缺一角的灯 423 | 灯与雪 403 | 点灯的远行者 336 | 点亮万盏灯 301 | 传灯者 298
灯与玄霜 152 | 守灯的人 142 | 执灯人 131 | 灯与灰雪 121 | 独照 118
九死未悔 41 | 雪落无声 14 | 灰雪无声 12 | 玄霜无声 8
```

**混合策略**（2000 局，一半随机、一半"贪财"）：

```
独照 400 | 缺一角的灯 385 | 传灯者 273 | 点亮万盏灯 235 | 灯与雪 225
点灯的远行者 127 | 守灯的人 101 | 灯与玄霜 91 | 灯与灰雪 72 | 执灯人 56
九死未悔 22 | 雪落无声 7 | 玄霜无声 4 | 灰雪无声 1 | 金灯无芯 1
```

**15 种结局全部可达**。注意这是乱点的分布——玩家一旦有意识地堆某条线，命中率会远高于此，这正是我们要的"选择有意义"。

## 10. 如何加第三条世界线（数据格式）

引擎完全数据驱动。在 `index.html` 的 `<script>` 里复制一个 `var XXX = {...}` 并 `WORLDLINES.xxx = XXX;` 即可，开始界面会自动多出一个入口。

```js
var XXX = {
  key:'xxx', name:'世界线名', sub:'一句话副标题', meta:'题材标签',

  // 五维属性的显示名（key 固定为 vit/men/arc/soc/coin）
  attrs:{vit:'体魄', men:'心力', arc:'才学', soc:'人情', coin:'积蓄'},

  // 可选的出身池 / 天赋池。不写就回落到引擎默认的现代版本（"父亲在厂里"之类），
  // 换皮世界线强烈建议自己写一套，否则一口现代腔会破功。
  families:[
    {n:'灶下人家',d:'父亲在矿脉打夜工',fx:{vit:-1,men:1}},
    {n:'寻常山民',d:'饿不着，也富不了',fx:{}},
    {n:'小有薄产',d:'祖父留下一间药庐',fx:{coin:2,soc:1,men:-1}}
  ],
  talents:[
    {n:'一副好根骨',d:'根骨 +2',fx:{vit:2}},
    {n:'一颗铁道心',d:'道心 +2',fx:{men:2}},
    {n:'一点灵窍',d:'悟性 +2',fx:{arc:2}},
    {n:'一副好相貌',d:'缘法 +2',fx:{soc:2}},
    {n:'身怀旧物',d:'灵石 +2',fx:{coin:2}}
  ],

  // 灯谱 18 盏 —— 顺序必须严格对应下方序号，不能改
  // 0念 1担 2守 3孝 4欠 5融 | 6路 7踮 8远 9滚 10追 11桥 | 12藏 13痴 14诚 15暖 16归 17传
  lamps:['念','担','守','孝','欠','融','路','踮','远','滚','追','桥','藏','痴','诚','暖','归','传'],

  names:['张三','李四', ...],                    // 姓名池
  prologue: function(s){ return ['段落1','段落2','p.ann||灰色提示段']; },
  birthText: function(s){ return '你是'+s.name+'…'; },

  events:[{
    id:'x1', n:'事件名', when:function(s){return s.age>=18}, text:'事件正文',
    out:[ {c:function(s){return s.attrs.vit>=6}, t:'结果A', fx:{attrs:{men:1}}},
          {t:'结果B（兜底）', fx:{attrs:{vit:-1}}} ]
  }],

  chapters:[{
    t:'第一章 · 标题', age:6,
    body:['段落'] 或 function(s){return ['按标记变化后的段落']},
    choices:[{
      k:'A', t:'选项文本',
      cond:function(s){return s.attrs.arc>=5},   // 可选，不写就是无条件
      lock:'才学不足 5：…',                       // cond 不满足时显示
      body:['结果正文'] 或 function(s){return [...]},
      fx:{lamps:{念:1}, attrs:{men:-1}, flags:{xxx:1}},   // fx 也可写成 function(s){return {...}}
      years:0,                                    // 可选，消耗年岁
      hint:'念↑｜心力↓'                            // 预知时显示
    }]
  }],

  endings:function(ctx){ /* ctx.lamps / ctx.attrs / ctx.flags / ctx.bucket / ctx.main / ctx.tough */
    if(ctx.tough>=3) return mkEnd('九死未悔','hidden','正文');
    var b=ctx.bucket;   // chuan|zhideng|yuanxing|guntang|shoudeng|quejiao|dengxue
    ...
  },
  epitaph:function(ctx){ return pick(pool[ctx.main] || ['这一局，我尽力了。']); }
};
WORLDLINES.xxx = XXX;
```

**性别代词**：正文里写 `{ta}`（爱人/异性同学：男版→她，女版→他）、`{子}`（儿子/闺女）、`{name}`（随机姓名），引擎渲染时自动替换。写世界线时不需要做男女双份文本。

## 11. AI 增强层（可选，全流程离线可玩）

原稿在序章、结算、墓志铭三处标了 ★AI 点。现在这三处已经落地为**可选项**：不配置也能完整游玩，配置后由玩家自己的模型服务生成。

### 11.1 接入方式

界面右上角 **AI** 按钮 → 填三项：

| 字段 | 说明 |
|---|---|
| 接口地址 | 任意 OpenAI 兼容端点。可填 `http://172.16.10.242:3000/v1`，引擎会自动补 `/chat/completions`；也可直接填完整的 `.../chat/completions` |
| 模型名 | 例如 `deepseek-v4-flash` |
| 密钥 | 可留空（自建网关通常不需要）。只存在本机 `localStorage`，不发往任何第三方 |

### 11.2 三个增强点

| 位置 | 触发 | 产出 |
|---|---|---|
| 序章 | 「✦ AI 写一句开局批注」 | 一句不超过 30 字的命运批注，按性别/出身/天赋生成 |
| 终章 | 「✦ AI 扩写这一生」 | 3–5 句结算散文 + 一句墓志铭，输入是完整的本局数据摘要（灯谱、属性、命运标记、13 次抉择、命中结局） |

### 11.3 防"AI 腔"的系统提示词

内置的 system prompt 直接写死了去 AI 味规则：**禁止"不禁 / 忍不住 / 一股暖流涌上心头"这类套话，禁止破折号排比，禁止解释自己写了什么，只输出正文**。意象统一约束在井 / 桥 / 雪 / 灯一组上。

### 11.4 失败兜底

任何网络失败、返回为空、未配置，都会：（1）不改变页面结构；（2）显示失败原因；（3）内置文案继续作为默认结局文本。

> 设计原则：**AI 是锦上添花，不是必需品**。断网、无额度、接口挂掉，都不影响一局完整的《人生之书》。

## 12. 灯·兼现（灯的等级在正文里显形）—— v2.1 新增

**解决的问题**：原来"灯升到 2 级 / 3 级"只体现在侧栏一个小数字上，正文毫无反应。玩家点了几十次灯，只在结算页才知道它们到底意味着什么。

**现在**：某一盏灯**首次**升到二档或三档时，当页正文下方会浮出一段专属文字：

```
灯 · 担　二档
扛事成了你的本能。别人还没开口，你已经把肩膀递过去。
```

| 项 | 说明 |
|---|---|
| 文案表 | `LAMP_TELL`，**18 条 × 2 档 = 36 段**，按灯的**序号**索引 |
| 触发点 | `apply()` 里检测 `after > before && after >= 2`，调用 `queueLit(k, after)` |
| 去重 | `S.lit['担@2']` 标记，一盏灯每个档位一生只浮一次（改命回退后不重复弹） |
| 渲染 | `litBlock()`，插在章节结果页正文与按钮之间；事件页同样生效 |
| 结算 | `deepLamps()` 在结算页追加「亮到最深的灯」板块，列出所有三档灯的文案 |
| 侧栏 | 三档灯用更深的底色（`#7d3f12`）＋更强光晕，与二档视觉区分 |

**为什么文案按序号共用而不是每线一份**：五条世界线的灯名不同（念 / 频 / 忆 / 问 / 念），但**语义按序号一致**（序号 0 都是"对母亲的牵挂"，16 都是"归乡"，17 都是"传承"）。所以 36 段文案一次写好、五线通用；需要时预留了 `WORLDLINES[x].tells` 覆写口子。

实测：200 局随机通关中 **200 局都至少触发一次兼现**，累计 1527 次（平均每局约 7.6 次）；**197 局**在结算页出现了「亮到最深的灯」。

## 14. 稀有结局《金灯无芯》二次修正 —— v2.1

**第一次修正（v2）**：条件从「积蓄 ≥7 且灯芯 ≤11」改为「积蓄 ≥8 且灯芯 ≤14」。理论下限虽然从"不可能"变成"可能"，但**实测 75,000 局随机通关仍然 0 命中**。

**根因**：两个条件在真实玩法里**负相关**——每个抉择至少点亮一盏灯，想让积蓄涨上去就得反复选"加钱"的选项，而那些选项同时也在加灯，灯芯值压不下来。实测随机玩法下 `积蓄≥8` 只占 0.26%，`灯芯≤15` 只占 1%，两者交集 ≈ 0。

**第二次修正**：先用「逐利偏置搜索」测出各线 `(积蓄, 灯芯)` 的**可达前沿**，再按线定阈值：

| 世界线 | 积蓄 ≥8 时实测最小灯芯 | 新阈值 |
|---|---|---|
| 小城浮世 | 15 | 灯芯 ≤ 15 |
| 赛博 · 霓虹井 | 15 | 灯芯 ≤ 15 |
| 仙侠 · 照心灯 | 13 | 灯芯 ≤ 14 |
| 民国 · 雪与刀 | 14 | 灯芯 ≤ 14 |
| 校园 · 十七岁的灯 | 15 | 灯芯 ≤ 15 |

修正后实测（每线 2500 局逐利打法）：

| 打法 | 命中率 |
|---|---|
| 一半随机一半逐利 | 0.04% – 0.16% |
| 明显逐利 | 0.04% – 0.48% |
| 极端逐利 | 0.08% – 0.44% |

**结论**：《金灯无芯》现在的定位是"**靠刻意玩法才拿得到**的隐藏结局"——随机玩几乎遇不到，但一条路走到底的玩家（疯狂攒钱、不为任何人点灯）一定会撞上它。这比"纯随机稀有"更贴合它的文本含义：你什么都有了，只是灯底下没有人。

> ⚠️ 红线（新增）：**任何数值型结局条件，都必须先算理论极值，再做一次"能不能真的走到"的偏置搜索验证**。只看公式成立就上线，等于埋了一个永远触发不了的死结局。

## 17. v2.3 增补：内容变体、平衡收紧与工程化

### 17.1 章节场景变体（同一线重玩不重样）

- 数据形态：某章写 `variants:N`，正文用 `s.v` 分叉（`s.v` 在进入该章时随机抽取并存档）：
  ```js
  { variants:2, body:function(s){ if(s.v===1)return['戏B']; return['戏A']; } }
  ```
- **补丁写法**：内容补丁的 `variants` 段只给"新增的场戏"，应用器会把现有正文自动包成第 0 场；且分支插在**最后一个顶层 return 之前**，所以按 `flags` 早返回的正文（辍学线第四章、未告别线第七章）优先于随机场戏。
- 实测（`tools/diversity-check.cjs`，每线 40 局随机通关）：五条线均 **12/12 章有两种以上场戏**，**不同整局数 39–40/40**（改造前 2/40）。

### 17.2 事件卡

- 每线 **30 张**（原 22），年龄覆盖 **6 岁起**（原最早 12 岁，导致第一章没有事件卡）；一章之间**概率连抽两张**（`S.event.extra`），一生遇到约 16 张。
- 事件卡文案按世界线本地化（赛博线的"钱/退税"→"信用点"等）。

### 17.3 隐藏结局收紧（平衡）

- 原条件"七盏主灯各 ≥1"过于宽松：随机乱点下校园线 **36.2%**、小城线 16.5% 就能拿到。

## 18. v2.4 玩法层：灯火道标 / 前尘 / 这一生

三条都是**贴着现有底盘长**的：不新增正文，不改任何结局判定，全离线可玩（AI 不参与）。
共同的设计红线：**灯只由人工写的 `fx` 点亮，任何玩法都不得放松稀有结局的阈值**。

### 18.1 灯火道标（把"随机重开"变成"有目的地点灯"）

开局前在开始界面立一盏灯，这一局专门去点它。

- **只做偏置，不做保底**：`rollBiasedStart()` 把出身与天赋各多抽 6 次，挑与该灯相性最高的一组
  （`LAMP_AFFINITY` 给出每盏灯关联的属性），相性 ≥3 就提前收手，避免退化成"指定出身"。
- **序章交代**：写明立的是哪盏、相性几分，以及"此刻暗着的是【X】"。
- **结算**：结局页给「点着 / 半亮 / 没点着」三档 + 一句话；跨局累计 `META.beaconStats`
  （点着/半亮/没点着次数 + 逐灯记录），开始界面道标选择器上用小圆点标出已点着过的灯。
- 新成就 **一灯到底**（对全部 18 盏灯都立过道标并且都点着了）。
- 实测（`tools/beacon-check.cjs`，60 局随机乱点）：偏置相性均值 ≈3.0、负值 0 次；
  单盏道标命中率 45%–67%（乱点基线），**说明偏置是"帮一手"，不是"必成"**。

### 18.2 前尘（上辈子的选择在这一世留痕）

- **灯痕**：上一局的**主灯**（`META.lastRun.mainIx`）这局开局就亮着（1 级，`litAge=0`），
  侧栏该灯挂「痕」标；对应那盏**缺口灯**在这一局**锁死**（`S.dimAge`），`apply()` 里直接拦掉，
  侧栏显示虚线 + 「缺」标。
- **旧账**：上一局最后那个抉择，在这一局以一张临时事件卡「旧 账」回访一次
  （正文带上辈子的原文、以及"始终没能点着【X】"）。
- **实现要点（踩过的坑）**：临时卡**绝不能** `unshift` 进 `W.events`——那是五条线共享的数据，
  每局插一张会让池子越玩越脏。改为整局只复制一次事件池 `S.evPool`，插在副本里。
  自检里专门有一条"再跑 15 局后池子仍为 30 张、遗留 0 张"。
- 不变量：**缺口灯整局亮不起来**（`beacon-check` 逐章断言，75+ 局 0 违章）。

### 18.3 这一生（结局页的抉择时间线）

- 结局页把 `S.log`（本来就有的结构化抉择记录）排成按年龄的时间线：
  `年龄 · 抉择字母 · 抉择原文 · 这一步点了哪盏灯`。
- 灯的年龄来自 `S.litAge`（在 `apply()` 里"从暗到亮"那一刻记录），
  `lampsAtChapter()` 用 `S.lit` 的 `k@lv@age` 标记反查"这一章点了哪盏灯"。
- 注意：事件卡点灯与章节同龄时不会被归到该章（`7/12` 左右命中），这是刻意的——宁可少标，不错标。

### 18.4 工程注意（改这三处必须成对改）

1. **灯名各线不同**：每条世界线的 18 盏灯各有各的字（origin 是「念担守…」，cyber 是「频载驻…」）。
   界面一律走 `lampName(ix[,wk])`，它同时兼容两种取值环境：
   生成页有 `LINE_META`（懒加载时 `WORLDLINES` 是空的），原型单文件走已注册的世界线。
   跨世界线的叙述（缺口、旧账）才用通用语义词 `BEACON_WORDS`。
2. **开始界面必须走 `metaOf()/metaKeys()`**：站点是懒加载的，首屏只有 `LINE_META` 可用。
   直接用 `WORLDLINES` 循环会让道标面板在线上根本不渲染（原型里却看不出问题）。
   另外 `LINE_META` **没有 `key` 字段**，行内 onclick 要传循环变量而不是 `meta.key`，
   `beaconToggle()` 也加了脏键校验（`"undefined"` 这类键直接忽略，不写坏存档）。
3. 新增的行内 onclick 函数要登记进 `split.cjs` 的 `handles`（`beaconToggle` / `beaconClear`），
   否则生成页里 `__pkBook.xxx` 是 undefined。

## 19. v2.5 玩法层：灯的对立 / 回头账 / 事件可选

### 19.1 灯的对立（选择第一次有了真正的"舍"）

  实现在 `apply()` 里、**加法之前**双向拦截。
- **对位**（按序号跨线通用，五条线自动共用同一套语义）：
  `[6]路 ↔ [2]守`、`[8]远 ↔ [3]孝`、`[9]滚 ↔ [14]诚`
- **硬约束：对立对必须跨结局桶**。同桶互斥会把那条结局线的等级和压死，让结局变成打不出来的死结局。
  `core-check.cjs` 里有一条断言：同桶对数必须为 0。
- **踩过的坑**：第一版只在"升到二档时把对位压下去"，**反方向漏了**——对位已经二档时，
  这一盏照样能升上去。实测 800 局 **330 次违章**。改成在加法之前双向拦截后为 0。
- 界面：被压住的灯侧栏显示 `⊘` 并降低不透明度，事件卡结算时补一句
  "灯 · X 被对位那盏压着，这一回只到一档"。
- **对可达性的实测影响**（`core-check.cjs`，偏置打法各 1200 局，清空 `LAMP_FOES` 做对照）：
  七灯全亮 有对立 263 / 无对立 284；独照 370 / 392；九死未悔 5 / 1。
  **稀有结局没有被压死**，只是更难了一点点。

### 19.2 回头账（中局反转）

- 前十一章攒下的 `flags` 过去只是结算时的描述，现在**第七章兑换一次**：这一段人生回过头来找你。
- 八个变体按 flag 匹配（`CALLBACKS`），一局只兑现一张，文案跨世界线通用（不用各线专有名词）。
- 效果是"改后半程的走法"：给一盏灯 + 改三四个属性，而不是只给一点数值。
- 事件卡上挂 `tag:'回头账'`，正文里显示一枚小标签、左侧描边加粗，让人一眼看出这不是普通事件。
- 实测（800 局）：96% 的局会兑现（`cb_ill` 需要生病，出现率最低）；**一局超过一次 0、早于第七章 0**。
- 实现要点与"旧账"一样：临时卡插在**整局复制的 `S.evPool`** 里，绝不碰共享的 `W.events`
  （跑完 800 局基础池仍是 30 张）。

### 19.3 事件卡可选（把事件从氛围升级成资源层）

- 数据形态：给事件卡加 `choices:[{k,t,cond?,fx}]`（`>=2` 个可用选项时才会拦玩家）。
  没有 `choices` 的卡走原来的自动路径（按 `out[].c(S)` 取第一条），**完全向后兼容**。
- 渲染走章节选项同一套 `.ch` 样式；点选后调 `chooseEv(i)` → 应用 `fx` → 进入结果页。
- 临时卡（旧账 / 回头账）**强制自动选中第一条**：它是"看着自己走过来"的一段，
  不该让玩家在四五个选项里翻找。
- 内容策略：**选项正文直接复用 `out` 里已有的 prose**，不新写一个字——
  否则要么造出一堆重复句，要么就得写两倍的正文。现覆盖五条线各 2 张，共 10 张。
- 实测（`core-check.cjs`）：600 局里玩家实际做过 **409 次**事件选择、异常 0、选完能走完一局。

### 19.4 工程注意（今天踩到的三个坑，都是"原型跑得出、上站跑不出"）

1. **新行内 onclick 函数必须登记进 `split.cjs` 的 `handles`**：
   `chooseEv` 我漏登记过一次——生成页里按钮调 `__pkBook.chooseEv` 而句柄表里没有，
   原型（全局函数）正常、线上点了报 undefined。`beaconToggle`/`beaconClear` 同理。
2. **生成页懒加载**：开始界面里任何按世界线遍历的东西都要走 `metaOf()/metaKeys()`，
   直接用 `WORLDLINES` 会得到空循环（v2.4 的道标面板就这么白过一次）。
3. **`LINE_META` 没有 `key` 字段**，别把 `meta.key` 传进行内 onclick。

## 20. v2.6：AI「另一种可能」（结局页的反事实）

### 20.1 为什么是它

预热缓存与结果改写已经铺好，反事实几乎是白捡的一层——**复用同一张缓存表、同一个流式管线**，
不需要新基建。它补的是"结局已定"之后的那点余味：不是重写这一生，是写那个回声。

### 20.2 分岔口怎么选

客户端 `aiAltPick()`：取**点灯最多的那一次抉择**（灯级求和，并列时取更晚的那次）——
那是这一生真正的分岔口。副作用是它天然偏向后段章节（灯越点越多）。

实测（1500 局模拟）分岔口落点：**第三章**在五条线里都是第一（3.4%~4.5%），
随后是第 6、12 章。要覆盖 80% 的分岔口需要 36 个 (世界线,章) 组合。

### 20.3 红线与提示词

与结果改写同一条红线：**模型只写"没走的那条路"，不得改写已经发生的结局**。
提示词里明确要求："不改变他既定的结局（《X》），那个结局已经发生了——把它当作回声，
不要重写它"，并禁止"可惜/幸好"这类判断、禁止"他明白了/从此以后"这类收束。

### 20.4 缓存与预热

- 键 = `'book-alt' + 世界线 + 抉择标题 + 结局`（`server.js` 的 cacheKey 分支），与玩家无关。
- 键空间约 **3150 条**（42 抉择 × 15 结局 × 5 线），全量 10 小时以上，**不能一次吃完**。
- 预热脚本 `tools/warm-rewrite-cache.cjs --alt` 改成**模拟采样**：跑若干局收集真实出现的
  (世界线, 抉择, 结局) 组合，按频率排序取前 N 条。默认 `--alt-runs 60 --alt-max 260`，
  实测可得 253 条（约 1.3 小时）。
- **分批跑**：先 60 条看命中率，再决定加不加；`--limit` 与 `--alt-max` 都支持截断。

### 20.5 工程注意

1. 提示词**不要在源文件里写换行转义**。这个坑我踩了三次（heredoc、Python 字符串、工具函数各一次）：
   `\n` 在多层转义里会被吃成真换行，把字符串字面量截断成语法错误。
   现在 `aiAlt()` 用 `[...].join(String.fromCharCode(10))` 拼行，源文件里一个反斜杠都不出现。
2. `aiAlt` 是行内 onclick，**必须登记进 `split.cjs` 的 `handles`**，否则线上点了报 undefined。
3. 服务端验证（本地桩上游，真跑 `server.js`）：第一次 `ok:true` 无 `cached`、同键第二次
   `cached:true`、换结局重新生成、缺 `pickTitle` 返回 `ok:false`——桩上游只被调用 2 次。

## 21. v2.5.1：外部评审文档的核实与修订（2026-09-16）

收到两份外部文档（《人生模拟器·批评与优化建议》《人生之书游玩报告》）。**先核实、再动手**——
结果头号主张就不成立，而真正的问题在文档没提到的地方。

### 21.1 逐条核实（不采信、只实测）

| 文档主张 | 实测 | 结论 |
|---|---|---|
| 「缺一角的灯」占 **59%**，结局偏科 | 六种策略 × 1200 局 = **7200 局**，缺一角 **13.8%**；中位两结局（缺一角+灯与雪）**25.7%**（文档建议"压到 40% 以内"——本来就在目标内） | **假**：17 周目样本太小 |
| 选择区分度不足，结局大量收敛 | 温情流→守灯的人 31%、打拼流→点灯的远行者 29%、死磕流→灯尽油枯 40%、攒钱流→独照 18% | **假**：不同打法顶级结局明显不同 |
| 「点亮万盏灯」几乎不可能 | 乱点 0.75%、刻意死磕 0.63%（条件放宽到"七盏全 2 档"后） | **真，但属设计**（隐藏结局，需刻意经营） |
| 五条世界线同构换皮 | 年龄序列/章数/灯数/事件池**完全一致**（6,15,17,18,22,28,29,40,45,52,60,78；12 章；18 灯；30 卡） | **真，属架构选择**（剧本换皮包，见题材换皮包文档） |
| 成长模拟器"老年段形同虚设" | `rensheng_baitai.js` 有 5 阶段，含 `暮年 · 回望 2045–2065` | **假**：评审只玩到 2033 就停了 |
| "点完只看到属性 ±N，灯在后台悄悄变" | 属性**完全没有** ±N 反馈；灯有 1.4 秒浮动提示 + 二档固定文案；选项的 `hint`（含"寿 +2"）被"预知"机制藏着，默认不显示 | **部分真**（见 21.3） |

**教训（和本仓库既有教训同源）**：17 局、走到 2033 就停——**样本不足的结论比没有结论更危险**，
因为它带着确定性的语气。两份文档的多数"缺陷"都是这么来的。

### 21.2 真 bug（文档没提，实测发现）：年龄结局吞掉稀有结局

v2.4⑥ 的「年龄维度」把寿数结局写成**无条件覆盖**：

```js
var end=W.endings(ctx);          // 先算出结局（含稀有/隐藏）
if(S.earlyDeath){...}
else { if(fa<=AGE_WHITE){...未及白首} else if(fa>=AGE_DRY){...灯尽油枯} }   // ← 直接替换
```

实测（各策略抽样）：

| 稀有结局 | 满足条件 | 修前拿到 | 被年龄结局吞 |
|---|---|---|---|
| 独照 | 1594 局 | 44% | **54%** |
| 九死未悔 | 37 局 | 68% | **30%** |
| 点亮万盏灯 | 9 局 | 100% | 0%（攒七盏的人寿数通常也短） |

**修法**：把稀有结局标成 `kind:'special'`（`kind` 字段此前无人消费，是纯元数据，改它零风险），
`finish()` 里只在"普通桶结局"上套年龄结局。**早夭不动**——那是"没活到终章"，本就该盖过一切。

修后：独照 44%→**83%**（被吞 0%）、九死未悔 68%→**92%**；整体分布几乎不变
（缺一角仍 13.8%、灯尽油枯 15.2%），说明这是"纠正不公平"，不是"放水"。

### 21.3 真缺口：事后反馈缺失

核实结论比文档说的更具体：**属性变化毫无反馈**（不是"看到 ±N"），灯只有 1.4 秒浮动提示，
而选项 `hint` 被"预知"机制藏着——默认情况下玩家选完确实不知道刚才改变了什么。

补一条**事后反馈**（`deltaLine`）：结果页与事件页各显示一行
`心力 -1　·　灯 · 念（新亮）` / `积蓄 +1　·　才学 -1　·　灯 · 担（升到二档）`。

- 只讲**已经发生**的事，不透露未来 → 不削弱"预知"（预知是选之前花代价看）
- 每步 `deltaReset()`，不串台；无变化时为空，不编造
- 实现：`apply()`/`applyYears()` 累积到 `S.delta`，`choose()`/`afterChoice()`/`chooseEv()` 三处重置

### 21.4 新增自检

`core-check.cjs` 追加两段：
- **⑥ 稀有结局不被年龄结局覆盖**：3000 局抽样，断言"被吞 0 局"且"年龄结局仍可达"
- **⑦ 事后反馈**：断言有变化时给内容、清空后为空、每步换新对象
